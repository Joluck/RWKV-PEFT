# RWKV-PEFT 代码整改计划

> 审查基线：`main` @ `5704c39`（cpu memory）
> 审查范围：`train.py`、`rwkvt/**`（3796 行）、`merge/`、`scripts/`、`pyproject.toml`
> 不在范围：`json2binidx_tool/`（上游 Megatron 数据工具，随仓库分发）、`cuda/`（CUDA 源码）

## 1. 结论摘要

| 维度 | 现状（整改前） | 结论 |
| --- | --- | --- |
| 正确性 | 3 处必然崩溃的 `NameError`、1 处必然崩溃的 `AttributeError`、3 处静默错配 | **P0 阻塞**，已修复 |
| 冗余 | 84 个 CLI 参数中 31 个从未被读取；5 个文件共 482 行完全无用；170 行注释掉的历史代码；`rwkv7/att.py` 有 4 份、`rwkv6/att.py` 有 3 份近似复制的 forward | **-1030 行（-25%）** |
| 规范 | 无 lint / format / 测试 / CI 配置；`from ... import *`、未定义名、魔法 env 变量、命名不统一 | 已建立 ruff + pytest + pre-commit 基线 |
| 可扩展性 | 每个后端/模式在 import 期用 env 变量分叉，导入即编译 CUDA；保存路径依赖 `deepcopy` 全量模型 | 部分重构，剩余见 §5 |
| FSDP2 | 模型结构天然适配，已实测可分片训练 | **好实现**，约 1~2 人日，详见 [fsdp2评估.md](./fsdp2评估.md) |

一句话：**代码能跑通主路径，但“隐性约定”太多（env 变量、`strict=False`、默认参数），冗余和安全网同时缺失**。本次先把「会崩的」「没人用的」「看不懂的」清掉，再按 §5 路线图推进。

## 2. 仓库结构

### 2.1 目录职责

```
train.py                        CLI 解析 + 派生配置 + 组装 Trainer（唯一入口）
rwkvt/
├── peft_loading.py             权重加载（meta init + mmap）、PEFT 装配、LightningModule 包装
├── infctx_module.py            循环状态容器（TimeMixState / ChannelMixState / BlockStateList）
├── utils.py                    无依赖小工具（strip_prefix / kwargs 过滤）
├── hf_compat.py                PEFT/transformers 需要的 5 个接口（mixin）
├── fsdp.py                     FSDP2：策略构造 / 分片 / 聚合保存 / CPU 端 merge
├── mtp.py                      多 token 预测头（--peft mtp，冻结底座）
├── spec_decode.py              MTP 投机解码（draft/verify + 接受率统计）
├── operator/
│   ├── rwkvop.py               WKV 后端选择：cuda(JIT) / fla(Triton) / triton(实验)

│   └── checkpoint.py           梯度检查点封装（torch / deepspeed 二选一）
├── rwkv5|6|7/                  三代模型的 model / block / att / ffn
├── lightning_train/
│   ├── light_rwkv.py           LightningModule：optimizer、training_step、L2Wrap
│   └── trainer.py              Callback：LR/WD 调度、日志、保存
├── dataset/
│   ├── dataset.py              MyDataset（纯数据层，不依赖 Lightning）
│   ├── datamodule.py           MyDataModule（DataLoader 接线）
│   ├── SFTdataset.py           hf datasets 分词 + 逐 batch padding
│   └── binidx.py               mmap 格式 .bin/.idx 读取
└── trick/lrs.py                cos / wsd 学习率
```

### 2.2 启动链路

```
python train.py --...
  ├─ build_parser()                       56 个参数
  ├─ finalize_args()                      校验 + 派生 dim_att/dim_ffn/real_bsz + 写 8 个 env 变量
  ├─ import rwkvt.*                       ← 此处才读 env：WKV / RWKV_MY_TESTING / RWKV_TRAIN_TYPE ...
  ├─ load_peft_model()
  │    ├─ build_model()                   meta device 构建 → torch.load(mmap) → assign=True
  │    ├─ apply_peft() / freeze_except_state()
  │    └─ RWKV(args, model)               LightningModule
  └─ Trainer(strategy=...).fit(model, MyDataModule)
       └─ TrainCallback                    LR/WD、loss_data.jsonl、wandb、保存
```

### 2.3 隐患最大的设计：env 变量驱动的隐式分叉

| 变量 | 取值 | 读取点 | 风险 |
| --- | --- | --- | --- |
| `RWKV_MY_TESTING` | x050/x060/x070 | `peft_loading`、`rwkvop`、各 model | 子串匹配（`"7" in s`），传错就静默选错模型 |
| `RWKV_TRAIN_TYPE` | none/state/infctx/fullstate | att/ffn 工厂、model、light_rwkv | 决定模块结构与 forward 签名 |
| `WKV` | cuda/fla/triton | `rwkvop` import 期 | **import 即编译 CUDA**，CPU/IDE 直接失败 |
| `FUSED_KERNEL` | 0/1 | att/ffn import 期 | 与 `--op` 组合出 8 种路径，无校验 |
| `RWKV_FLOAT_MODE` | fp32/bf16 | CUDA kernel 分支 | 与 `--precision` 拼写不同，易错配 |

本次把「读取点」收敛到 `train.py::finalize_args()` 一处并加了校验，但**分叉仍在 import 期**，见 §5 P2-1。

### 4.4 行为变更（**升级前必读**）

1. **默认值**：`--precision fp16 → bf16`；`--my_testing x052 → x070`；`--optimizer none → adamw`（`none` 仍接受，等同 adamw）；`--data_type utf-8 → binidx`（且只允许 binidx/sft/jsonl）。
2. **移除参数**（原本就被解析但从未使用，见附录 A）：`--dropout --pre_ffn --head_qk --tiny_att_dim --tiny_att_layer --my_pile_version --my_pile_shift --my_pile_edecay --ds_bucket_mb --my_sample_len --my_ffn_shift --my_att_shift --my_pos_emb --magic_prime --my_qa_mask --my_random_steps --my_exit --my_exit_tokens --train_parts --quant --loss_mask --mask_id --lisa_config --lora_config --pissa_config --miss_config --avg_loss --fla --dataload get`。
   若你的本地脚本传了这些参数，会得到 argparse 的 `unrecognized arguments` —— 这是有意的（静默无效比报错更危险）。
3. **`--dataload only` 语义**：截断到 `ctx_len`，不再假定 `bsz=1`。
4. **`epoch_save` 生效**：原来是每 epoch 都存，现在按 `--epoch_save` 存（`0` 表示只在最后存）。
5. **`--load_partial` 生效**：默认缺 key 直接报错。
6. **state/fullstate 的 `v` mask** 与 base 对齐（SFT padding 场景数值会变，属修 bug）。
7. **SFT 数据**：不再把整个数据集 pad 成一张大张量，改为逐 batch；`--sft_num_proc`、`--tokenizer_path` 新增为可配置项。

## 5. 后续整改路线图

### 阶段 P2-1（1~2 天人日）：把「import 期副作用」拆掉

**为什么先做这个**：它同时卡住测试、IDE、CPU 调试、FSDP2 接线。

- `rwkvop.py` 改为 `build_ops(op: str, train_type: str) -> Ops` 工厂，不再在 import 期 `load()`；
  模型层从 `args.ops` 取函数，`train.py` 在 `finalize_args` 后调用一次。
- 合并 fp32/bf16 两份 CUDA wrapper（差异只有断言与 `-D_FP32_` flag）。
- 验收：`python -c "import rwkvt.rwkv7.model"` 在无 nvcc、无 GPU 的机器上成功；`pytest` 不再需要 `_cpu_stub` 里的 kernel 替换。

### 阶段 P2-3（0.5 天）：依赖与配置预检

- 统一报错文案：`配置 X 需要依赖 Y，请 pip install ...`。

### 阶段 P3（1~2 天）：可观测性与文档

## 6. 代码规范方案

### 6.1 分层与命名

| 层 | 规则 |
| --- | --- |
| 入口 | `train.py` 只做「解析 → 校验 → 组装 → 启动」，不放训练逻辑 |
| 装配 | `*_loading.py` 只做对象构建，不抛训练期异常 |
| 模型 | `rwkv{N}/` 只依赖 `args` + 算子，**不许** import lightning/deepspeed |
| 训练 | `lightning_train/` 只依赖 Lightning 与模型，不许读 `os.environ`（改用 `args`） |
| 工具 | `_` 前缀为内部实现；公开函数必须有 docstring（一行说清「做什么/返回什么」） |
| 命名 | 类 `CamelCase`（`TrainCallback`），函数/变量 `snake_case`，常量 `UPPER`；不用拼音/无意义缩写（`args`、`idx`、`B/T/C` 这类张量维度名保留） |

### 6.2 类型与文档

- 公开函数加类型注解（返回 `torch.Tensor`/`None` 这类），内部热路径可省略；
- 张量形状写在 docstring：`Args: x (B, T, C)`；
- 所有 `os.environ` 读取必须集中到 `finalize_args()`，其他模块用 `args.*`；
- 魔法数字（如 `1e-4 / token_amount`、`0.5`）就地注释来源。

### 6.3 工具链

| 工具 | 配置 | 用法 |
| --- | --- | --- |
| ruff | `pyproject.toml [tool.ruff]`，`line-length=120`，规则 `E,F,W,I,UP,B,SIM,C4,RUF` | `ruff check .` |
| pytest | `tests/`，`tests/conftest.py` 注入路径与 env 快照 | `pytest -q` |
| pre-commit | `.pre-commit-config.yaml`（ruff + 空白/EOF/yaml 检查） | `pre-commit install` |
| editorconfig | `.editorconfig`（utf-8/lf/4 空格，md/toml 2 空格） | 编辑器自动读取 |

**格式化的引入节奏**：本次**没有**跑 `ruff format`，因为整仓重排会把语义改动淹没在 diff 里。
建议单独一个 `style: apply ruff format` 提交（无逻辑改动 + 平价测试通过后合并）。

### 6.4 测试策略（三层）

1. **纯函数层**（快，毫秒）：`strip_prefix`、`PadCollator`、`BlockStateList`、CLI 校验。
2. **CPU 模型层**（秒级）：`tests/_cpu_stub.py` 替换 WKV 算子，验证形状、状态传递、梯度流、grad_cp 等价、FSDP2 分片。
3. **单卡 GPU 冒烟**（分钟级，CI 缺省跳过）：`--data_type binidx` 跑 20 step，断言 loss 下降、checkpoint 可被 `--load_model` 重新加载。

`tests/cpu_parity.py` 是重构期工具：改动模型层前后各 dump 一次，`compare` 逐位比对。

### 6.5 提交与评审

- 提交前缀：`fix:` / `refactor:` / `perf:` / `docs:` / `test:` / `chore:`；
- 一个提交只做一件事：**删除/移动代码的提交不做行为改动**，行为改动单独提交；
- PR 模板三问：改了什么行为？怎么验证的？回滚方式？
